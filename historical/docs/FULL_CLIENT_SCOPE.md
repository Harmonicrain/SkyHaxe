# SkyHaxe browser-client scope

The target is the component graph prepared by the original `HabboMain`: configuration,
localization, window manager, communication, Navigator, friends/messenger, inventory, toolbar,
catalog, room engine/UI, avatar editor, notifications, help, ads, moderation, Wired, sound,
quests, friend bar, groups, games, free-flow chat and the new Navigator.

Conversion is not runtime adoption. Every source progresses through four explicit states:
**converted**, **compiles**, **wired**, and **browser-verified**. Broad conversion and compilation
take place in isolated `.toolchain/vNN` roots. The current runnable client does not consume a new
candidate until its original component/service graph is ready for an intentional cutover.

## Excluded infrastructure

- `splash/` and the root Flash/AIR loader: HTML owns download progress and application startup.
- `onBoardingHcSteps` and unrelated onboarding movies: separate Flash movies, not services inside
  the main client component graph. The 57-file v33 original loading-screen closure intentionally
  includes the required `onBoardingHcUi` loader classes and assets.
- `flash.*`, AIR native APIs and `mx.*`: target-platform APIs. Missing behavior is implemented only
  as a narrow browser/OpenFL compatibility contract with a semantic test.

`com/hurlant` remains in the compile candidate. Its big-integer, hashing and Diffie–Hellman code is
directly required by the original communication contract; treating the whole namespace as obsolete
would force a handwritten protocol replacement. Runtime adoption may still replace individual
entropy or VM-memory calls at their narrow browser boundaries.

`deng/fzip` also remains in the isolated compile candidate because the original `LibraryLoader`
contract names it. This does not select that Flash-era downloader for the browser runtime: wiring
still resolves asset loading to the existing `SwfFile`/HTML5 boundary. Keeping the original types
available at state 2 avoids replacing a large original contract merely to satisfy compilation.

`org/openvideoads` remains in the isolated compile candidate: the original loading UI names its
VAST model and utility classes, and that conversion work is already useful coverage for the shared
converter. NGH's active `external_dev_vars.txt` sets `interstitials.2016.enabled=false`; therefore
the VAST video player is compiled for graph fidelity but is not an enabled SkyHaxe runtime feature.
This is separate from the older `interstitial.enabled=true` image-interstitial path, which remains
supported. No converted VAST code is deleted merely because its runtime feature flag is off.

SnowStorm/BattleBall and the original `HabboGames` owner remain in scope. Whether their servers
are enabled is a product/runtime decision, not a reason to corrupt the client dependency graph.

The historical scope inventory is generated by `evidence/v30_full_client_scope.py` into
`evidence/v30_full_client_scope.json`. The supported working composition is now
`reproducibility/v32/composition.json`; the v30 inventory remains useful evidence but is no longer
the authoritative build composition.
